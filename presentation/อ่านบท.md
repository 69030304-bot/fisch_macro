

## รายละเอียดงานแยกตามสมาชิก

ส่วนนี้ใช้ทำสไลด์ “หน้าที่สมาชิก” และให้แต่ละคนทบทวนบทของตัวเอง โดยระบุทั้งงานย่อย เครื่องมือ/เทคโนโลยี และไฟล์ที่เกี่ยวข้อง คำว่า “เครื่องมือ” ด้านล่างหมายถึงเทคโนโลยีที่ใช้ในระบบตามเอกสารโครงการ ไม่ได้ระบุโปรแกรมออกแบบภายนอกที่ repo ไม่ได้ยืนยัน

### 69030304 — นายชยภัทร พุทธศรีเมือง

**บทบาท:** Python Application & Automation Core  
**ขอบเขตงานและงานย่อย:**

1. เชื่อมการทำงานของแอปกับระบบอัตโนมัติผ่าน `fisch_macro.py` ซึ่งเป็นตัวประสานระหว่าง Dashboard, Core และ Workflow
2. ออกแบบวงจรชีวิตการทำงานของ Macro ใน `core/engine.py` และสถานะใน `core/state.py` เช่น เริ่ม ทำงาน หยุด และ error
3. ใช้ `core/events.py` ส่ง event และสถานะระหว่างโมดูล โดยไม่ผูก automation เข้ากับหน้าจอโดยตรง
4. เขียนลำดับการตกปลาใน `automation/workflow.py` และแยกงานย่อยใน `automation/operations.py` เช่น เตรียมเบ็ด เหวี่ยง รอจังหวะ และดึงปลา
5. ทำการจับภาพและตรวจจับใน `vision/capture.py` กับ `vision/detection.py` โดยใช้ `mss`/PIL, ภาพพิกเซลและ NumPy color mask รวมถึงการจัดกลุ่มตำแหน่งพิกเซล
6. ทำ tracking และคำนวณการควบคุมใน `vision/tracking.py` และ `automation/controller.py` (EMA, PD controller และ Sigma-Delta)
7. เชื่อมการส่งอินพุตเมาส์/คีย์บอร์ดผ่าน `core/input.py` พร้อม cancellation, failsafe และการปล่อยปุ่มเมื่อหยุด

**เทคโนโลยีหลัก:** Python, NumPy, mss/PIL, Win32 `SendInput` ผ่าน input abstraction, `MockInputDriver`/`MockScreenGrabber` สำหรับจำลองการทดสอบ, Git branch ตามส่วนงาน  
**สาธิต/เปิดไฟล์:** แสดง workflow diagram, `automation/workflow.py`, ภาพ preview ที่ตรวจจับปลา/แถบ, หรือทดสอบ F6/F7 โดยใช้สภาพแวดล้อมที่เตรียมไว้  
**บทพูดของสมาชิก:** “ผมรับผิดชอบแกนการทำงานอัตโนมัติ ตั้งแต่จัดการสถานะและลำดับ workflow ไปจนถึงการจับภาพ ตรวจจับตำแหน่ง ติดตามการเคลื่อนที่ และคำนวณอินพุตควบคุม ผมแยกงานเหล่านี้เป็นโมดูล Python เพื่อให้ทดสอบ logic ด้วย mock ได้ และมีระบบยกเลิกกับ failsafe สำหรับหยุดงานครับ”

### 69030208 — นายฤทธิพร วงค์ป้อม

**บทบาท:** GUI & Database Integration  
**ขอบเขตงานและงานย่อย:**

1. ลงมือทำหน้าต่าง Desktop ด้วย Tkinter ใน `gui/auth_window.py`, `gui/dashboard.py` และ `gui/admin_dialog.py`
2. ทำหน้าล็อกอิน สมัครสมาชิก และกู้รหัสผ่าน พร้อมเชื่อมฟอร์มเข้ากับ API
3. ทำ Dashboard แสดงสถานะ สถิติสด พรีวิวภาพ ตั้งค่า log และปุ่มเริ่ม/หยุด
4. เชื่อม API ฝั่ง Desktop ผ่าน `gui/client.py` (`ApiClient`) และส่ง request ที่ใช้เวลานานไปรันเบื้องหลังด้วย `run_bg` เพื่อไม่ให้ UI ค้าง
5. ทำหน้าจัดการบัญชี/ผู้ดูแล และเครื่องมือดูฐานข้อมูลใน `view_database.py` โดยเชื่อมการเรียกข้อมูลตามสิทธิ์ผ่าน API ตามขอบเขตของระบบ
6. พัฒนา widget ที่ใช้ซ้ำใน `ui_kit.py` และ `gui/widgets.py` เช่น Card, Button, Slider, Tabs, Tooltip และ DateField

**เทคโนโลยีหลัก:** Python, Tkinter/ttk, `requests` สำหรับ HTTP client, worker/background task, `ui_kit.py`, Git  
**สาธิต/เปิดไฟล์:** เปิดหน้า Login และ Dashboard, แสดงการตั้งค่าหรือหน้าต่างบัญชี, ชี้ `gui/client.py` ว่า request วิ่งเบื้องหลังอย่างไร  
**บทพูดของสมาชิก:** “ผมรับผิดชอบการพัฒนา GUI และเชื่อม Desktop เข้ากับ backend ครับ หน้าจอหลักเขียนด้วย Tkinter แยกเป็นหน้า login, dashboard และ account dialog ส่วนการเรียก API ใช้ ApiClient และ background worker เพื่อให้หน้าจอยังตอบสนองระหว่างรอเครือข่ายครับ”

### 69030377 — นางสาวพิชชาภา ภูววิไลเมธา

**บทบาท:** UX / UI Design  
**ขอบเขตงานและงานย่อย:**

1. กำหนดแนวทางภาพรวมและลำดับการใช้งานของหน้าจอ เช่น เข้าสู่ระบบ → Dashboard → ตั้งค่า/Calibration → เริ่มควบคุม
2. กำหนด design system ใน `docs/UI_SPEC.md` ได้แก่สีหลัก สีสถานะ ฟอนต์ ระยะห่าง และรูปแบบองค์ประกอบ
3. แยกธีม `MAIN` สำหรับ Dashboard/Admin กับ `LOGIN` สำหรับหน้าสมาชิก พร้อมกำหนดสีที่สื่อสถานะ idle, ทำงาน, เตือน และ error
4. ระบุหลักการออกแบบ เช่น สถานะต้องมองเห็นง่าย, controls ต้องปรับได้สะดวก และงานนานต้องไม่ทำให้ UI ดูเหมือนค้าง (ประสานกับผู้พัฒนา GUI)
5. กำหนดแนวทาง component และหน้าจอ เช่น card, ปุ่ม, tabs, sliders, live preview, calibration loupe, tooltips และ admin table เพื่อให้ผู้พัฒนานำไปสร้างจริง
6. ทำงานร่วมกับนายฤทธิพรเพื่อทบทวนว่า UI ที่เขียนสอดคล้องกับแนวทางและผู้ใช้เข้าใจได้

**เครื่องมือ/สิ่งส่งมอบที่ยืนยันใน repo:** Design specification ใน `docs/UI_SPEC.md`, theme/component specifications ใน `ui_kit.py` (ตัว implementation ร่วมกับ GUI developer)  
**ข้อควรพูดให้ตรง:** เอกสารโครงการระบุงาน UX/UI และสเปกการออกแบบ แต่ไม่ได้ระบุชื่อเครื่องมือ mockup ภายนอก จึงอย่าระบุ Figma/โปรแกรมอื่น เว้นแต่สมาชิกยืนยันว่าได้ใช้จริง  
**สาธิต/เปิดไฟล์:** เปรียบเทียบ LOGIN กับ MAIN theme, อธิบายสีสถานะและลำดับการใช้งานจากหน้า Dashboard  
**บทพูดของสมาชิก:** “ดิฉันรับผิดชอบออกแบบประสบการณ์และแนวทางหน้าตาของระบบ กำหนดลำดับการใช้งาน สี ธีม ฟอนต์ และส่วนประกอบที่ต้องมีไว้ใน UI specification จากนั้นประสานกับผู้พัฒนา GUI เพื่อให้หน้าจอจริงใช้งานและสื่อสถานะได้ตรงตามแบบค่ะ”

### 69030343 — นายธีระนิตย์ บุญทวี

**บทบาท:** Backend & Database Developer  
**ขอบเขตงานและงานย่อย:**

1. สร้าง API ด้วย FastAPI ใน `main.py` สำหรับ health, register, login, user profile, logout, password change/reset และ admin actions
2. แยกกฎทางธุรกิจและ validation ไว้ใน `service.py` ไม่ให้ route รับผิดชอบทุกอย่างเอง
3. ออกแบบ SQLite schema สำหรับ `users`, `sessions`, `login_logs` รวม index, foreign key และ migration ผ่าน `database.py`/`data/`
4. แยกการเข้าถึงข้อมูลเป็น repositories ใน `data/repositories.py` และใช้ model ใน `data/models.py`
5. จัดการรหัสผ่านและ token ใน `security.py` เช่น PBKDF2-HMAC-SHA256, token แบบสุ่มที่ปลอดภัย และการตรวจ session
6. ทำการส่งข้อมูลไป Google Sheets ใน `sheets.py` และ receiver ฝั่ง Apps Script ใน `google_apps_script.js` โดยไม่ส่งรหัสผ่าน hash หรือ token ออกไป

**เทคโนโลยีหลัก:** Python, FastAPI, SQLite, SQL, PBKDF2-HMAC-SHA256, HTTP/JSON, Google Apps Script/Google Sheets  
**สาธิต/เปิดไฟล์:** เปิด `/docs` ของ FastAPI (ถ้า backend พร้อม), แสดงภาพความสัมพันธ์ Desktop → API → Service → SQLite และอธิบายตารางผู้ใช้/เซสชัน  
**บทพูดของสมาชิก:** “ผมรับผิดชอบ backend และฐานข้อมูลครับ FastAPI รับคำขอจาก Desktop แล้วส่งให้ service ตรวจข้อมูลและสิทธิ์ก่อนอ่านหรือเขียน SQLite ผมแยก repository สำหรับตารางต่าง ๆ และใช้การ hash รหัสผ่านกับ session token เพื่อให้การจัดการสมาชิกเป็นสัดส่วนและควบคุมได้ครับ”
